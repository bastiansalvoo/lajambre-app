# Resumen General del Proyecto "La Jambre"

A continuación se detalla el estado actual del proyecto, dividiendo sus principales tecnologías y funcionalidades tanto para el Backend como para el Frontend.

## ⚙️ Backend (Servidor y API)
El backend está construido con una arquitectura moderna, modular y robusta basada en Node.js, encargándose de toda la lógica de negocio y seguridad.

### Stack Tecnológico Base
- **Framework:** NestJS (Node.js), el cual provee una arquitectura altamente escalable basada en módulos, controladores y servicios.
- **Lenguaje:** TypeScript, para un tipado estricto que reduce errores en tiempo real y hace el código más seguro.
- **Base de Datos:** PostgreSQL.
- **ORM:** Prisma. Permite definir la base de datos de manera declarativa y realiza consultas seguras y rápidas hacia PostgreSQL.
- **Autenticación:** Sistema seguro basado en JWT (JSON Web Tokens), `Passport.js` para las estrategias y `bcrypt` para encriptar las contraseñas de los usuarios.
- **Integraciones:** SDK de Transbank, el cual permite transacciones y validaciones de compra a través de Webpay Plus.
- **Tareas Programadas (Cron Jobs):** Utiliza `@nestjs/schedule` para verificar y procesar automáticamente la expiración de puntos.

### Estructura y Módulos Principales (Modelos de Base de Datos)
- **Usuarios (Users):** Sistema con dos permisos distintos (`USER` y `ADMIN`). Maneja datos de envío, perfiles y la cantidad de puntos disponibles (`pointsBalance`).
- **Catálogo (Products & Categories):** Sistema de gestión de menús. Los productos están atados a una categoría y pueden estar disponibles o no, incluyendo descripciones y precios.
- **Agregados / Adicionales (Extras):** Elementos que el usuario puede sumar opcionalmente a un producto individual al meterlo en el carrito (ej. "Extra Queso", "Papas agrandadas").
- **Pedidos (Orders & OrderItems):** Compleja gestión de órdenes (carritos de compra) que maneja diferentes estados (PENDIENTE, PAGADO, EN_CAMINO, ENTREGADO, CANCELADO). Contabiliza el costo de despacho (`deliveryFee`) y vincula directamente con Transbank mediante el seguimiento de `buyOrder` y `sessionId`.
- **Sistema de Puntos y Fidelidad (PointTransactions):** Lógica que registra los movimientos de puntos: cuántos puntos se ganan por orden, cuáles se utilizan en un canje, cuándo expiran (90 días de plazo estándar) y la recompensa utilizada (`rewardType` como delivery gratis, etc).

## 📱 Frontend (Aplicación Móvil)
El frontend contiene la interfaz gráfica que instalarán los usuarios o administradores, enfocado a plataformas iOS y Android.

### Stack Tecnológico Base
- **Framework Visual:** React Native montado sobre Expo. Esto permite desarrollar para iOS y Android desde un mismo código base de TypeScript.
- **Navegación:** Expo Router. Transforma la estructura de las carpetas en el árbol de navegación o rutas de la aplicación (muy similar al comportamiento de Next.js pero para móviles).
- **Diseño y Estilos:** NativeWind (Tailwind CSS). Permite estilizar toda la app rápidamente utilizando clases utilitarias modernas sin depender exclusivamente de hojas de estilo aisladas.
- **Conexión a Datos:** Utiliza `Axios` para conectarse a las rutas del Backend y `@tanstack/react-query` para guardar el caché de información, evitar pantallas de carga innecesarias y sincronizar el catálogo o los puntos con el servidor en tiempo real.

### Estructura y Bloques de la Aplicación
El proyecto cuenta con un sistema de enrutamiento agrupado para dividir la experiencia:
- **Flujo de Acceso `(auth)`:** Pantallas dedicadas exclusivamente a iniciar sesión, registrarse o recuperar una contraseña sin que interfiera el resto de la navegación.
- **Flujo de Clientes `(client)`:** Espacio de la aplicación dedicado a los usuarios normales. Aquí interactúan con el catálogo, añaden artículos al carrito, ven sus puntos de "La Jambre" y hacen seguimiento a sus pedidos en curso.
- **Flujo de Administrador `(admin)`:** Dashboard especial al que solo tienen acceso los usuarios con `role: ADMIN` para revisar comandas pendientes, cambiar su estado (por ejemplo, a "EN_CAMINO"), o editar si un producto sigue en stock.
- **Resultado de Pago:** Rutas nativas específicas (como `webpay-result.tsx`) que atrapan el callback o retorno que hace Webpay a la app una vez que se autoriza (o deniega) la transacción en la pasarela bancaria.

### 🎯 Resumen Funcional del Proyecto:
Se trata de un e-commerce y sistema de gestión de pedidos gastronómico integral ("La Jambre"). Abarca todo el flujo: desde que un usuario entra y se registra, explora el menú por categorías y añade productos con extras a su carrito, hasta que paga real y seguramente a través de Transbank. Además de vender, tiene un componente fuerte de gamificación/fidelidad, donde los clientes juntan puntos virtuales por cada compra, que luego pueden ser usados para obtener beneficios en forma de canje o recompensas, todo dentro de una aplicación móvil robusta y moderna.
