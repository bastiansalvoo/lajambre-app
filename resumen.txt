# Resumen Detallado y Estado Actual del Proyecto "La Jambre"

Este documento contiene un desglose completo del estado de la plataforma "La Jambre", separando lo que ya está implementado y lo que se encuentra pendiente de desarrollo, para que tengas un mapa de ruta claro de tus siguientes pasos.

---

## 1. BACKEND (NestJS + Prisma + PostgreSQL)
**Estado General:** Avanzado y sólido. La arquitectura modular está completa y la base de datos está modelada para soportar todo el ciclo de negocio.

### Estructura de la Base de Datos (Prisma)
- **`User`**: Gestiona usuarios, roles (`ADMIN`, `USER`), direcciones y saldo de puntos. Tiene un sistema de `verificationToken` para confirmar emails.
- **`Product` & `Category`**: Productos vinculados a categorías. Incluyen campos de precio, imagen y disponibilidad (`isAvailable`).
- **`Extra`**: Permite definir agregados a los productos.
- **`Order`, `OrderItem`, `OrderItemExtra`**: El corazón transaccional. Guarda el total, `deliveryFee`, dirección real de entrega (`deliveryAddress`), teléfono de contacto y los datos de Webpay (`buyOrder`, `sessionId`). Sus estados van desde `PENDIENTE` hasta `ENTREGADO` o `CANCELADO`.
- **`PointTransaction`**: Registro histórico de puntos (`EARNED`, `REDEEMED`, `EXPIRED`), vital para el sistema de fidelidad y cronjobs de expiración.

// Configuración básica del generador y la fuente de datos
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
}

// --- ENUMS ---
enum Role {
  USER
  ADMIN
}

enum OrderStatus {
  PENDIENTE
  PAGADO
  EN_CAMINO
  ENTREGADO
  CANCELADO
}

enum PointTransactionType {
  EARNED
  REDEEMED
  EXPIRED
}

// --- MODELOS DE DATOS ---

model User {
  id                Int       @id @default(autoincrement())
  email             String    @unique
  password          String
  name              String
  phone             String
  address           String?
  role              Role      @default(USER)
  orders            Order[]

  // --- SISTEMA DE PUNTOS ---
  pointsBalance     Int                @default(0)
  pointTransactions PointTransaction[]

  // --- SISTEMA DE VERIFICACIÓN ---
  isVerified        Boolean   @default(false)
  verificationToken String?   // Guardará el código secreto temporal

  createdAt         DateTime  @default(now())
  updatedAt         DateTime  @updatedAt
}

model Category {
  id       Int       @id @default(autoincrement())
  name     String
  products Product[]
}

model Product {
  id          Int         @id @default(autoincrement())
  name        String
  description String
  price       Int
  image       String?
  isAvailable Boolean     @default(true)
  category    Category    @relation(fields: [categoryId], references: [id])
  categoryId  Int
  orderItems  OrderItem[]
}

model Extra {
  id              Int              @id @default(autoincrement())
  name            String
  price           Int
  isAvailable     Boolean          @default(true)
  orderItemExtras OrderItemExtra[]
}

model Order {
  id           Int         @id @default(autoincrement())
  user         User        @relation(fields: [userId], references: [id])
  userId       Int
  status       OrderStatus @default(PENDIENTE)
  total        Int
  deliveryFee  Int         @default(1250)

  // --- NUEVOS CAMPOS ---
  deliveryAddress String?   // Para guardar dónde se entregó físicamente
  contactPhone    String?   // Para el repartidor
  // ---------------------

  pointsEarned      Int                @default(0)
  pointsUsed        Int                @default(0)
  rewardType        String? 
  pointTransactions PointTransaction[]

  buyOrder  String? @unique
  sessionId String?

  items     OrderItem[]
  createdAt DateTime    @default(now())
  updatedAt DateTime    @updatedAt

  @@index([userId])
}

model OrderItem {
  id              Int     @id @default(autoincrement())
  order           Order   @relation(fields: [orderId], references: [id])
  orderId         Int
  product         Product @relation(fields: [productId], references: [id])
  productId       Int
  quantity        Int
  priceAtPurchase Int

  extras OrderItemExtra[]

  @@index([orderId])
  @@index([productId])
}

model OrderItemExtra {
  id              Int       @id @default(autoincrement())
  orderItem       OrderItem @relation(fields: [orderItemId], references: [id])
  orderItemId     Int
  extra           Extra     @relation(fields: [extraId], references: [id])
  extraId         Int
  priceAtPurchase Int

  @@index([orderItemId])
  @@index([extraId])
}

// --- HISTORIAL DE PUNTOS ---
model PointTransaction {
  id        Int                  @id @default(autoincrement())
  user      User                 @relation(fields: [userId], references: [id])
  userId    Int
  order     Order?               @relation(fields: [orderId], references: [id])
  orderId   Int?
  points    Int // Positivo si gana, negativo si canjea
  type      PointTransactionType
  expiresAt DateTime? // Fecha de vencimiento (90 días)
  createdAt DateTime             @default(now())

  @@index([userId])
}


### Módulos y Controladores de la API
- **`auth.controller`**: Maneja el flujo de login (retorna JWT), registro y envío de correos (nodemailer) para verificación. Contraseñas encriptadas con `bcrypt`.
- **`users`**: Permite la lectura y modificación de perfiles y balances de puntos.
- **`products.controller`, `categories.controller`, `extras.controller`**: API completa para el CRUD (Crear, Leer, Actualizar, Borrar) del menú del restaurante.
- **`orders.controller`**: Recibe las solicitudes de pedidos, interactúa con el SDK de Transbank (`transbank-sdk`) para generar pagos y procesa los webhooks/redirecciones de Webpay.

## 2. FRONTEND (React Native + Expo)
**Estado General:** En pleno desarrollo. La estructura (Expo Router, Tailwind, Zustand, React Query) está lista. Tienes flujos avanzados y otras pantallas como *stubs* (en construcción).

### Arquitectura Técnica del Cliente
- **Framework:** React Native 0.81 bajo Expo SDK 54.
- **Navegación:** `expo-router` con rutas protegidas según roles.
- **Estilos:** `nativewind` (Tailwind CSS) configurado globalmente.
- **Manejo de API:** `@tanstack/react-query` y `axios` para consumo de datos.
- **Estado Local:** `zustand` (actualmente gestionando el `cartStore`).
- **Seguridad:** `expo-secure-store` para guardar el `userToken` de forma encriptada.
