# REPORTE TÉCNICO DE ARQUITECTURA: LAJAMBRE APP
Fecha: 29 de abril de 2026
Autor: Tech Lead / Software Architect

## 1. RESUMEN EXTENSO DE LA SOLUCIÓN
Lajambre App es una solución Full-Stack diseñada para la alta demanda de un sistema de delivery moderno.

### Infraestructura de Backend (NestJS + Prisma)
*   **Gestión de Datos:** Se utiliza PostgreSQL con Prisma ORM. La base de datos está normalizada para manejar la complejidad de órdenes con múltiples productos y extras, además de un historial detallado de transacciones de puntos.
*   **Seguridad:** Implementa un flujo de autenticación robusto mediante Passport-JWT. La verificación de identidad se realiza mediante un `verificationToken` generado con `crypto`, asegurando que solo usuarios reales operen en la plataforma.
*   **Lógica de Negocio:**
    *   **Sistema de Fidelización:** Incluye un Cron Job (`cleanExpiredPoints`) que se ejecuta diariamente a las 03:00 AM para invalidar puntos con más de 90 días.
    *   **Gamificación:** El sistema calcula niveles (Bronce/Plata/Oro) basados en `puntosHistoricos` para mantener el estatus del cliente independientemente de los canjes realizados.
    *   **Control de Tienda:** Posee validación de horarios y multiplicadores dinámicos de puntos (1.5x los martes).

### Frontend (Expo + React Native)
*   **Estado Global (Zustand):** El carrito implementa una "Huella Digital" (`cartItemId`). Esto permite que si un cliente pide dos "Burger Clásicas" pero una con "Extra Tocino" y otra sin, el sistema las trate como ítems independientes en el carrito y en la orden final.
*   **Experiencia de Usuario:** Animaciones con Reanimated y carga asíncrona optimizada con TanStack Query para una sensación de fluidez nativa.
*   **Administración:** Posee módulos de "Live Orders" y "Menu Manager" para la gestión operativa en tiempo real.

## 2. VEREDICTO DE COMPLETITUD (MVP)
**Estado: 90% Completado.**
El proyecto cubre todos los flujos críticos de un MVP: Registro -> Selección -> Compra -> Pago -> Historial. 
*   **Justificación:** La integración con Transbank es funcional, el sistema de lealtad está automatizado y la separación de roles es efectiva. Falta cerrar el flujo de "Notificaciones Push" y el manejo de errores de pago para considerarlo 100% MVP.

---

## 3. GAPS Y FALTANTES (REQUERIMIENTOS MODERNOS)
1.  **Recuperación de Fallos de Pago:** Si Webpay falla, la orden queda en estado "PENDIENTE", pero el usuario no tiene un botón directo en la App para "Reintentar Pago" sin crear una orden nueva.
2.  **Notificaciones en Tiempo Real:** Se requiere Socket.io o FCM para notificar al cliente cuando su pedido pase de "Preparando" a "En Camino" sin que tenga que refrescar la pantalla manualmente.
3.  **Geocodificación:** El campo de dirección es texto libre. Se recomienda integrar Google Places para asegurar que el despacho esté dentro del radio de entrega permitido. (esto segun yo no)
4.  **Validación de Stock:** Aunque existe el switch `isAvailable`, no hay un contador de stock numérico que evite sobreventas de productos limitados.(esto segun yo no)

## 4. VEREDICTO DE PRODUCCIÓN: "NO-GO" ❌
A pesar de la excelente calidad del código, el sistema **no es apto para producción real hoy** por los siguientes motivos de seguridad y configuración:

*   **Credenciales:** El sistema aún utiliza el Commerce Code y API Key de integración (pruebas) de Transbank.
*   **Configuración Crítica:** El control de horarios de la tienda está comentado en `OrdersService.ts`. Un despliegue así permitiría pedidos fuera de horario.
*   **Servicio de Correo:** Nodemailer requiere una configuración de SMTP de producción (ej. SendGrid/Amazon SES) en lugar de cuentas locales o de prueba.
*   **Exposición de Datos:** Se recomienda una auditoría final a los DTOs para asegurar que no se filtren contraseñas o tokens en las respuestas del API de usuarios.

**Acción recomendada:** Resolver los puntos de configuración crítica y migrar a credenciales de producción para cambiar el dictamen a "GO".
